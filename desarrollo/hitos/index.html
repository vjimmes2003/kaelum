Hitos del proyecto

Esta sección resume los puntos de avance más importantes de Kaelum. No muestra microtareas, sino momentos clave que consolidan el proyecto como idea, como documentación y como portfolio web.

Ver roadmap Ver devlog

Qué se considera un hito aquí

Un hito no es cualquier tarea terminada. Se considera hito todo aquello que cambia la madurez del proyecto: cuando una parte deja de ser una idea suelta y pasa a convertirse en una capa sólida del portfolio.

Línea de hitos principales

01

Identidad del proyecto definida

Kaelum ya no se plantea como idea difusa, sino como shooter con propuesta clara, tono y pilares reconocibles.

02

GDD estructurado

La documentación principal organiza narrativa, sistemas, UI, sonido, mercado, monetización y planificación.

03

DAFO y CAME resueltos

El proyecto no solo está descrito: también está analizado y defendido desde sus riesgos y oportunidades.

04

Web portfolio construida

La presentación pasa a una estructura navegable con juego, media, documentación, desarrollo y contacto.

05

Devlog activo

El avance del proyecto se comunica como evolución real y no solo como resultado final.

06

Cierre de apartados evaluables

Presupuesto, métricas, equipo, roadmap e hitos refuerzan el portfolio de cara a la entrega.

Por qué importa mostrar hitos

  • Demuestra evolución real del trabajo.
  • Hace visible el esfuerzo estructural, no solo el resultado bonito.
  • Ayuda a leer el proyecto como proceso y no como entrega improvisada.

Relación con la evaluación

Tener hitos visibles refuerza la parte de planificación, experiencia de usuario y lectura profesional del portfolio, porque deja claro que el proyecto tiene progresión y seguimiento.

Siguiente capa de crecimiento

Una vez cerrados estos hitos base, el proyecto queda mejor preparado para una fase posterior de mejora: más pulido visual, materiales promocionales, refinamiento de contacto y expansión del media kit.
